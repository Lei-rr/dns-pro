# dns-pro

DNSPod / Cloudflare / Cloudflare for SaaS / Cloudflare Tunnel / Tencent Cloud EdgeOne integrated DNS and tunnel management panel.

`dns-pro` is a single-user operations panel for managing DNS zones, DNS records, SaaS hostnames, acceleration domains, and Cloudflare Tunnel routes from one UI. The project is built with Node.js, Fastify, TypeScript, Vue 3, and Vite. Runtime configuration is stored in JSON files, so it can be deployed without a database.

## Features

- DNSPod zone and DNS record management
- Cloudflare zone and DNS record management
- Cloudflare for SaaS custom hostname management
- Cloudflare fallback origin management
- Preferred CNAME domain list for SaaS workflows
- Cloudflare Tunnel creation, token rotation, install guide, and public hostname routes
- Tencent Cloud EdgeOne zone and acceleration domain management
- Optional DNS side-effect sync and cleanup for SaaS / EdgeOne / Cloudflared workflows
- Single-user session authentication

## Tech Stack

- Backend: Node.js 20+, TypeScript, Fastify, Zod
- Frontend: Vue 3, Vite, TypeScript, Vue Router, Pinia, Ant Design Vue
- Storage: local JSON files under `data/`
- External APIs: Cloudflare REST API, Tencent Cloud API signing for DNSPod and EdgeOne

## Project Structure

```text
dns-pro/
├── src/
│   ├── app.ts                 # Fastify app composition
│   ├── server.ts              # Server entry
│   ├── config/                # Provider definitions
│   ├── controllers/           # HTTP handlers
│   ├── gateways/              # External API clients
│   ├── middleware/            # Fastify hooks
│   ├── repositories/          # JSON file persistence boundary
│   ├── routes/                # Fastify route plugins
│   ├── schemas/               # Zod validation schemas
│   ├── services/              # Domain services and workflows
│   ├── support/               # Shared infrastructure
│   └── types/                 # Shared TypeScript types
├── web/                       # Vue 3 + Vite frontend
├── data/                      # Runtime JSON storage, ignored by Git
├── dist/                      # Backend build output
└── package.json
```

The frontend source lives in `web/`. Fastify does not render Vue source files; it only serves the production assets generated by Vite under `web/dist/`. This keeps the frontend and backend modular while still allowing a single-process deployment.

## Quick Start

```bash
git clone https://github.com/<your-name>/dns-pro.git
cd dns-pro
npm install
```

On first run, missing runtime files use built-in defaults and are written when settings are saved from the UI. The default login is:

```text
username: admin
password: admin
```

To change the login before first start, create `data/config.json`:

```json
{
  "auth": {
    "username": "admin",
    "password": "change-me"
  }
}
```

Run development server:

```bash
npm run dev:server
```

Run frontend development server in another terminal:

```bash
npm run dev:web
```

Build production assets:

```bash
npm run build
npm start
```

The backend serves the built frontend from `web/dist/`.

## Environment Variables

| Variable | Default | Description |
|---|---|---|
| `HOST` | `127.0.0.1` | Backend listen host |
| `PORT` | `2022` | Backend listen port |
| `SESSION_SECRET` | development fallback | Cookie session signing secret. Set a strong value in production. |
| `NODE_ENV` | unset | Set to `production` to enable secure cookies |
| `LOG_LEVEL` | `info` | Fastify logger level |

`SESSION_SECRET` should be at least 32 characters in production.

## Provider Credentials

Credentials are configured from the UI after login and stored in `data/providers.json`.

### DNSPod

Use Tencent Cloud `SecretId` and `SecretKey` with DNSPod permissions:

- `DescribeDomainList`
- `CreateDomain`
- `DeleteDomain`
- `DescribeRecordList`
- `CreateRecord`
- `ModifyRecord`
- `DeleteRecord`

### Cloudflare

Use a Cloudflare API token. Required permissions depend on enabled modules:

| Feature | Permission | Scope |
|---|---|---|
| Zone list | Zone / Zone / Read | Target zones |
| DNS records | Zone / DNS / Edit | Target zones |
| Cloudflare for SaaS | Zone / SSL and Certificates / Edit | Target zones |
| Cloudflare Tunnel | Account / Cloudflare Tunnel / Edit | Target account |

`account_id` is required for zone creation and Cloudflare Tunnel APIs.

### EdgeOne

EdgeOne reuses a linked DNSPod provider credential. The Tencent Cloud key needs EdgeOne and DNSPod permissions:

- EdgeOne: `DescribeZones`, `DescribeAccelerationDomains`, `CreateAccelerationDomain`, `ModifyAccelerationDomain`, `ModifyAccelerationDomainStatuses`, `DeleteAccelerationDomains`, `ModifyHostsCertificate`
- DNSPod: record read/write permissions if DNS sync is enabled

## Provider Relationships

```text
edgeone     -> dnspod       # reuse Tencent Cloud credentials
saas        -> cloudflare   # Cloudflare for SaaS
saas        -> dnspod       # optional DNS sync target
cloudflared -> cloudflare   # tunnel and route CNAME management
```

## Development

Useful commands:

```bash
npm run lint
npm run typecheck
npm run typecheck:web
npm run build
npm run verify
```

Backend route modules are Fastify plugins. Controllers only read validated inputs, call services, and return responses. Provider API calls belong in `gateways/`. Local JSON persistence belongs in `repositories/`. Cross-module side effects should be handled in workflow services and returned through `side_effects`.

Frontend modules are grouped by provider under `web/src/modules/`. Shared components and request utilities live under `web/src/shared/`. The production build uses route/module-level code splitting.

## Deployment

Build first:

```bash
npm install
npm run build
```

Run with your preferred process manager:

```bash
HOST=127.0.0.1 PORT=2022 SESSION_SECRET="replace-with-a-long-random-secret" NODE_ENV=production npm start
```

Example Nginx reverse proxy:

```nginx
location / {
    proxy_pass http://127.0.0.1:2022;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

Ensure `data/` is writable by the Node.js process user.

## Data Files

Runtime files are intentionally ignored by Git:

- `data/`

Missing JSON files fall back to built-in defaults. Provider credentials and SaaS preferences are created when saved from the UI.

## Security Notes

- Do not commit real provider credentials.
- Use HTTPS in production.
- Set a strong `SESSION_SECRET`.
- Change the default `admin/admin` login after deployment.
- Prefer least-privilege API tokens for Cloudflare and Tencent Cloud.
